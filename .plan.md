# Operator Dashboard, Instance Grid & Transaction History Plan

## Context
Operators currently land on a generic instance grid (`PayWorkspace`) after login, then navigate into a multi-step payment form. The user wants:
1. Operators get a proper dashboard (like admin) scoped to their instance, with a "New Collection" button and payment type cards
2. Admin `/instances` page should be a card grid of all instances with collection stats
3. Transaction history page with filters
4. The `/pay` page (instance grid) becomes redundant

## Changes Overview

### 1. Extend AuthContext to expose `instanceId`
**File:** `lib/auth-context.tsx`
- Add `instanceId: string | null` to `AuthContextType`
- Parse it from cookie on mount (format: `"operator|<instanceId>"`)
- Operators get their instanceId; admins get `null`

### 2. Update Navigation
**File:** `app/components/sidebar.tsx` + `app/components/mobile-nav.tsx`

Admin nav: **Dashboard** (`/dashboard`), **Instances** (`/instances`), **Operators** (`/operators`), **Logs** (`/logs`)

Operator nav: **Dashboard** (`/pay`), **Transactions** (`/pay/transactions`), **Profile** (`/profile`)

### 3. Reroute `GET /pay` — Operator Dashboard
**File:** `app/pay/page.tsx`
- Operators: render `OperatorDashboardClient`
- Admins: redirect to `/dashboard`

### 4. Create Admin Instances Grid
**New files:**
- `app/instances/page.tsx` — server component, admin-only
- `app/instances/instances-grid-client.tsx` — card grid of all instances

Each card shows: instance name, split code, total collections count, total amount collected. Links to `/instances/{id}`. Admin-only (operators redirected to `/pay`). Includes "Configure New Instance" button linking to `/pay/configure`.

### 5. Create Operator Dashboard Component
**New file:** `app/pay/operator-dashboard-client.tsx`

Layout:
- **Hero card** — instance name, split code, total collected
- **Metric cards** — Total Revenue, Successful Payments, Pending Payments
- **"New Collection" button** — prominent CTA → `/pay/{instanceId}`
- **Payment Type cards** — one per payment type, clickable → `/pay/{instanceId}?paymentType={ptId}`
- **Recent 5 Transactions** — payer, amount, status, date. "View all" → `/pay/transactions`

### 6. Pre-select Payment Type in Collection Form
**File:** `app/pay/payment-collection-form.tsx`
- Read `?paymentType={ptId}` from URL on mount
- Auto-set `selectedPaymentTypeId`, jump to step 2

### 7. Create Transaction History Page
**New files:**
- `app/pay/transactions/page.tsx`
- `app/pay/transactions/transaction-history-client.tsx`

Filters: date range (from/to), payment type dropdown, search by reference/payer. Results: table (desktop) / card list (mobile) with pagination.

### 8. Extend Collections API for Filtering
**File:** `app/api/collections/route.ts`
- Accept: `fromDate`, `toDate`, `paymentTypeId`, `search`
- Prisma `where` conditions for date range, type match, payer/reference search

### 9. Extend RTK Query
**File:** `lib/store/api/collectionsApi.ts`
- Add `getFilteredCollections` endpoint with filter params
- Keep existing `getCollections` for simple fetch

### 10. Remove PayWorkspace
**Delete:** `app/pay/pay-workspace.tsx` — redundant
